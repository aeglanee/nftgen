## Code bugs

### High

- [x] **C1 include with a wrong/missing section rendered nothing** — a
  typo'd `rule:` or a file under the wrong list gave an empty
  `policy: drop` chain (lockout with `flush ruleset`). Now: include file must
  be a mapping with only `rules:`/`sets:`, the requested section must exist
  and be a list (`rules: []` ok, blank `rules:` errors); vars fragments must
  be lists; leftover "skip include" placeholders raise. — 05923cd
- [x] **C2 named service set dropped the proto** — `web: [80/tcp, 443/tcp,
  443/udp]` named + `proto: udp` opened udp/80 (inline was correct). Now a
  `(proto . port)` pair set (`tcp . 80`), matched as
  `meta l4proto <p> meta l4proto . th dport @set`; proven on the wire (B27).
  — 8b7a0de
- [x] **C3 port vmaps ignored the proto** — `th dport vmap { 22 : … }` for
  `ssh: [22/tcp]` matched udp/22 too. Now `meta l4proto . th dport vmap
  { tcp . 22 : … }`; bare numbers need `/tcp`; `[proto, dport]` concats take
  the row's proto's ports; proven on the wire (B22). — ce46a2a

### Medium

- [x] **C4 `nftgen build <typo-root>` exits 0** — creates an empty
  `<root>/generated/` and builds nothing (also with `--check`). No hosts
  found should be an error. Now: zero host policies → error before anything
  is written (covers missing root, empty root, empty `policies/hosts/`).
- [x] **C5 empty concat set with an address field** — typed `ipv6_addr . …`
  (family unknown) and the rule renders `None saddr . …`. Runtime-filled
  concat sets are a real use case → a `family:` key, or an error.
  Now: `family: ip|ip6` — required with an address field and no tuples;
  must agree with tuples; rejected without `saddr`/`daddr`. Also fixed
  concat-authoring.md claiming nftgen auto-splits mixed v4/v6 (it errors).
- [x] **C6 a chain without `hook:` silently drops `type:`/`policy:`/
  `priority:`** — becomes a regular chain, no error. Now an error (none in
  nftgen or sessrumnir configs used it).
- [ ] **C7 value shapes unchecked** — `ct: established` (string) renders
  `ct state e,s,t,…`; `dport: [80, 443]` / `iifname: [a, b]` crash with a
  TypeError; `proto: [tcp, udp]` unsupported and unchecked.
- [ ] **C8 ignored or crashing sub-keys** — `log: {prefx: x}` silently drops
  the prefix; `log: false` crashes; `icmp-type` silently drops
  `dport`/`sport`; `action: {jump: a, goto: b}` / `{}` crash; a non-mapping
  table spec crashes. The CLI only turns BuildError/DefinitionError/
  FileNotFound/YAMLError into clean errors.

## Design outcomes (agreed in discussion)

- **Services = protocol + port, always.** No port-only services; a
  hand-written `type: inet_service` set covers the rare port-only need.
- **Named vs inline must never differ** in what they let through.
- **Strictness:** keys are checked everywhere, values mostly not → a schema
  for values is the agreed direction (covers C7, C8, C15).
- **Definitions:** shared names across kinds, mixed v4/v6 named sets, and
  required interface groups all error loudly → fine as is. Value checks at
  definition time (`22/tpc`, `99999/tcp`) → later.
- **JSON output is out** (rule IR refactor dropped with it).
- **Two front ends, keep both:** file tree (CLI; tests, examples) and vars
  mode (sessrumnir). Document both (D1).
- **Parked:** `proto: [tcp, udp]` / `dport:` without `proto` — leaning to a
  pair-set form (`meta l4proto . th dport { tcp . 53, udp . 53 }`).
